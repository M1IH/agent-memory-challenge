## 口径与复现

- 作者数据：`Mohammadta/BEAM@3205395e897e7318c7b094ef4e6047b9b82dbb03` 的 100K Parquet，5,429,768 字节，SHA-256 `c0519be25907005ba873c927c50877471d550873039d96c041554d0075a78ace`。
- 选取规则：按数值 `conversation_id` 排序，1–14 为 development；15–20 保留，**本轮没有运行或查看其探针结果**。每段对话选 `summarization`、`multi_session_reasoning`、`knowledge_update` 各两题，合计 84 题。
- 输入：仅 `chat` 消息写入第四版 `MemoryStore`，每条原消息单独 Add，`session_id` 为原始 batch。若单条消息超过 Add 的 200,000 字符上限，则无损切分并仍映射至同一原消息 ID。Search 只传探针的 `question`，关闭 embedding，Top-K 100。
- 标注：从 `source_chat_ids` 递归展开整数、列表、字典取得所需**消息** ID，仅在 Search 之后计分。`rubric`、理想答案、`conversation_plan`、`narratives`、`user_profile` 均未写入 Add 或 Search。部分题可能存在标注不完备；命中来源消息也不等于答案正确。
- 运行：设置本地 `PYTHONPATH` 包含 `data/.beam-deps` 和项目根目录，执行 `python -m benchmarks.probe_beam_100k --output data/beam-100k-dev-14.json --development-conversations 14`。逐题报告保留在 Git 忽略目录，当前报告 SHA-256 `f8b0f0d09037df360f15409cb7b17ea964bda861855730a9e351582c153e595a`。脚本和 `app/store.py` 的运行时 SHA-256 分别为 `cc9be2b6bf3e47a60ad9dc72514496d00e637cb478b53a00116da4170a121e70`、`ae8959b22d893edb9d1062b7dba48d9a8551bfaccce729a25241cc19953a12a0`。先前未记录消融开关的初版报告 SHA-256 为 `be94f0d4d02c7e6caaaafa09c29ab9c1c33ca20951998a39c6324a5e2bd75d3d`；两次基线数字一致。

对未进入 Top-100 的所需消息进一步核对原始历史：摘要题有 116 条（用户 64、助手 52），长度中位数 1,344 字符；跨会话推理 47 条（用户 42、助手 5），中位数 220 字符；知识更新 11 条（均为用户消息），中位数 219 字符。摘要缺失分布于所有 batch，并非单条超长消息切分就能解释。下一步应检查相关性排序和多证据覆盖，同时保留短用户消息的召回。

所需消息与问题的词法交集诊断：摘要题未检出的 116 条所需消息均至少有一个共同词；跨会话推理未检出的 47 条中有 46 条如此；知识更新 11 条全部如此。这个检查含常见词，不能证明主题相关性，但说明“完全没有共同词”不是主要解释。

## 关联噪声与候选否决（2026-10-22）

逐题回看一条知识更新问题“最终论文草稿有多少词”：第四版前五条是关于被动语态、查重、阅读技巧等助手长回复；关闭关联时，记载“最终草稿达到 4,700 词”的用户消息升至第一。当前英文实体提取会把长回复中标题式大写普通词（如 `Paraphrase`、`Long`、`Drafts`）当成桥接实体，多个低频普通词叠加的关联加分足以压过直接事实。这是一个可复现的误扩展机制，但并不能证明所有关联均应关闭。

离线尝试过滤句首和列表标题式英文词：BEAM 84 题摘要完整 Top-100 从 3/28 **降到 2/28**；跨会话从 11/28 到 12/28，知识更新保持 22/28。摘要任一来源 Top-5 逐题 3 改善、2 回退，完整 Top-100 有 1 回退、0 改善。报告 SHA-256 `447631ba4c74817032936fbb40c36a9ed5f7cfb89c8bd269c8e0d67e8735be11`。此过滤候选淘汰，不改生产。

全局关闭关联还在独立来源 LongMemEval-S development 390 题交叉验证：来源 Complete@5 从 228→243（23 改善、8 回退），但 Complete@100 从 385→382（1 改善、4 回退）；报告 SHA-256 `968f93f8d2db4387b8bb0897dc89bbfc63a34611bbe07c0ec0a1bc2111ff6601`。固定本地 Qwen 4B、同一 30 题、Top-5 的严格 EM 从 5→6，唯一变化是 `The Glass Menagerie.` 与 `The Glass Menagerie` 的句号差别，两边所需来源均已完整进入结果；没有实质答题收益。答案报告 SHA-256 `536901fb0ec90457f439edc98f959718f43256f954d8eabe9c85b076a80a366a`。**全局关闭关联淘汰**。这些均非官方成绩。

## 长回复占位与内容组织实验（2026-10-22）

为诊断摘要来源缺失，基线重跑时记录了 Top-100 的来源 ID、分数和返回字符数；84 题指标不变，逐题报告 SHA-256 `c4e1e4c393dd79f322f923b20dbd090822d1cf603cc95eb661f6b4ca80079dd3`。摘要题的历史中用户与助手消息各占 50%，返回前 100 条却有 **2,108/2,800 条（75.3%）为助手消息**。摘要所需消息中，用户 98 条只找回 34 条；助手 142 条找回 90 条。Top-100 返回内容中位数为 **339,069.5 字符**。这是字符数，不是官方 tokenizer 的 token 数，不能直接断言超过 Answer 窗口。

先保留原前五条，从 Top-300 中补足每题至少 50 条用户消息：摘要所需用户消息找回 34→51，但助手消息 90→65，完整 Top-100 **3/28→1/28**（0 改善、2 回退）；跨会话推理 11→15，知识更新保持 22。摘要返回字符中位数降至 223,083.5。报告 SHA-256 `e17b518666d97a20384ee30c1325f730c54d533f76a3147c8bb35b328571b0c7`。**角色配额淘汰**，因为它以损失摘要所需助手证据换取用户召回。

再把助手原消息无损切为最多 1,200 字符的片段，取 Top-300 候选后按原消息 ID 去重，保留最靠前的 100 个不同来源：摘要完整 Top-100 **3/28→2/28**（0 改善、1 回退），跨会话推理 11→13，知识更新保持 22；跨会话与知识更新任一所需消息 Top-5 分别 9→20、10→20。摘要返回字符中位数降至 89,019.5。报告 SHA-256 `e96df7ac6a3ceaa7e7e2507d20fb4e1e373f9e14336da941d85716ddcd3e6489`。小样本中不去重的切片方案曾让跨会话完整 Top-100 3/4→2/4；去重才恢复。**统一切片方案暂不进入生产**：摘要仍回退，且来源 ID 命中不能说明被检出的片段包含所需事实；还没有答案级、延迟和容量验证。

这两组结果把“多来源全局摘要”和“短事实检索”区分为不同瓶颈。下一轮应针对长历史摘要设计可验证的全局压缩表示，而不能用角色配额或统一切片来替代摘要能力；对短事实的切片收益也须先过独立答案级和 Free 容量门禁。

## 下一步

**2026-10-25 批次均衡反例：**基线 Top-300 中，摘要题的全部标注来源有 25/28 题可找齐，而 Top-100 仅 3/28；这是可重排空间的上界观察，不代表存在有效的无答案重排规则。用[固定离线脚本](../benchmarks/probe_beam_batch_round_robin.py)保留原前五条，再将第 6–300 条按原 Add batch 轮流选至 100 条。相同 84 题上，摘要完整来源 Top-100 **3→2**（0 改善、1 回退），跨会话 **11→11**，知识更新 **22→19**（0 改善、3 回退）。脚本校验 BEAM 原始文件及 Top-300 报告的 SHA-256，来源标签只在选完后计分。**淘汰按批次平均分配**；历史覆盖均匀不能替代问题相关性，也没有答案级收益证据。该反例未修改生产检索。

先分析摘要题的所需消息为何落在 Top-100 之外：区分多来源占位、同一 batch 的消息片段、超长消息切分和问题与证据用词不一致。针对明确原因设计一个有界候选，并在相同 84 题上比较完整覆盖、知识更新回退及内容预算；候选还须过独立答案级和正式容量门禁，才有资格进入下一次 Smoke。
