## 口径与复现

- 作者数据：`Mohammadta/BEAM@3205395e897e7318c7b094ef4e6047b9b82dbb03` 的 100K Parquet，5,429,768 字节，SHA-256 `c0519be25907005ba873c927c50877471d550873039d96c041554d0075a78ace`。
- 选取规则：按数值 `conversation_id` 排序，1–14 为 development；15–20 保留，**本轮没有运行或查看其探针结果**。每段对话选 `summarization`、`multi_session_reasoning`、`knowledge_update` 各两题，合计 84 题。
- 输入：仅 `chat` 消息写入第四版 `MemoryStore`，每条原消息单独 Add，`session_id` 为原始 batch。若单条消息超过 Add 的 200,000 字符上限，则无损切分并仍映射至同一原消息 ID。Search 只传探针的 `question`，关闭 embedding，Top-K 100。
- 标注：从 `source_chat_ids` 递归展开整数、列表、字典取得所需**消息** ID，仅在 Search 之后计分。`rubric`、理想答案、`conversation_plan`、`narratives`、`user_profile` 均未写入 Add 或 Search。部分题可能存在标注不完备；命中来源消息也不等于答案正确。
- 运行：设置本地 `PYTHONPATH` 包含 `data/.beam-deps` 和项目根目录，执行 `python -m benchmarks.probe_beam_100k --output data/beam-100k-dev-14.json --development-conversations 14`。逐题报告保留在 Git 忽略目录，当前报告 SHA-256 `f8b0f0d09037df360f15409cb7b17ea964bda861855730a9e351582c153e595a`。脚本和 `app/store.py` 的运行时 SHA-256 分别为 `cc9be2b6bf3e47a60ad9dc72514496d00e637cb478b53a00116da4170a121e70`、`ae8959b22d893edb9d1062b7dba48d9a8551bfaccce729a25241cc19953a12a0`。先前未记录消融开关的初版报告 SHA-256 为 `be94f0d4d02c7e6caaaafa09c29ab9c1c33ca20951998a39c6324a5e2bd75d3d`；两次基线数字一致。

每题均返回 100 条消息。摘要题的来源消息通常较多，且完整覆盖最弱；28 题中 26 题至少找回一条所需消息，但只有 3 题全部找回。跨会话推理也有类似的分散证据问题。知识更新所需消息较少，完整覆盖明显更高。以上统计是**来源消息覆盖代理**，不是 BEAM 作者的 LLM rubric 评测，也不是 AML F1 或最终答案正确率。

对未进入 Top-100 的所需消息进一步核对原始历史：摘要题有 116 条（用户 64、助手 52），长度中位数 1,344 字符；跨会话推理 47 条（用户 42、助手 5），中位数 220 字符；知识更新 11 条（均为用户消息），中位数 219 字符。摘要缺失分布于所有 batch，并非单条超长消息切分就能解释。下一步应检查相关性排序和多证据覆盖，同时保留短用户消息的召回。

所需消息与问题的词法交集诊断：摘要题未检出的 116 条所需消息均至少有一个共同词；跨会话推理未检出的 47 条中有 46 条如此；知识更新 11 条全部如此。这个检查含常见词，不能证明主题相关性，但说明“完全没有共同词”不是主要解释。
