## 不可改变的决策与门禁

- 采用“评测驱动的混合升级”：保留已验证的 FastAPI、SQLite、鉴权、持久化、
  Docker 和发布链路，逐步增加结构化事实状态、时序有效期、冲突治理、多跳证据分组
  和轻量重排。
- 官方 Smoke 只验证已经在冻结独立集合上证明有效的候选。检索 Hit@K 单独提升，
  不能构成提交理由；必须同时观察下游最终答题正确率或可信代理指标。
- 首次 Full 只有在 Smoke 至少恢复并超过历史最佳 `0.5175347222` 后才讨论，且必须
  再取得用户明确授权。不得自动付款、升级套餐、注册或提交 Full。
- 官方评测材料不能用于训练、调参、传播或伪装成本地测试。合成测试和公开数据集结果
  必须明确标注来源，不能称为官方成绩。
- 每个代码候选都要经过：复现问题 -> 回归测试 -> 独立集合 -> 完整测试 -> 容量门禁
  -> 代码审查与秘密扫描 -> 提交推送 -> 精确 SHA CI。

### P0-A：建立能指导提分的端到端评测

1. [x] 明确路线 B、历史分数基线、官方提交边界和恢复规则。
2. [x] 定义统一公开评测样例格式：对话/记忆、问题、答案、证据来源、能力标签、
   时间点、语言、数据许可和原始样例标识。
3. [ ] 建立数据集登记表，逐一核验 PersonaMem、LoCoMo/LoCoMo-Refined、CLBench、
   BEAM、LongMemEval、ScriptMem 的公开地址、许可证、任务字段、可重复下载方式和
   与本赛道的适配边界；无法核实的集合不得纳入。
4. [ ] 为每个可用集合编写只做格式转换的适配器，保存来源版本和内容哈希；不改写
   正确答案，不从测试集反推生产规则。
5. [ ] 按来源数据的官方划分优先；没有官方划分时，用固定随机种子建立
   `development / frozen_holdout`，冻结后只允许评测，不允许看答案调规则。
6. [ ] 实现统一检索评测：Recall/Hit@1/3/5/10/100、MRR、全部必要证据
   Complete@K、冲突证据排序、禁止证据侵入和按能力/语言分组结果。
7. [ ] 实现下游答题评测接口，把检索 Top-K 交给固定回答器；记录回答器身份、参数、
   prompt 哈希和运行成本。先支持可复现的本地/规则基线，再评估是否值得调用模型。
8. [ ] 实现答案评分：选择题准确率；短答案采用数据集官方 scorer；缺少官方 scorer
   时同时报告规范化 Exact Match 与 token F1，人工判断不得混入自动主分。
9. [ ] 加入“无检索 / BM25 / 当前混合检索 / 候选检索”四组对照，区分回答模型能力
   与记忆系统贡献。
10. [ ] 生成不可覆盖的基线报告，绑定数据版本、适配器哈希、代码 SHA、配置、运行环境
    和逐题结果；报告必须说明哪些集合是公开、合成或代理指标。
11. [ ] 在 CI 中加入小型许可安全样本；大型数据集只保存下载脚本和哈希，不把许可不明
    或体积过大的原始数据提交仓库。

**P0-A 出口门禁：** 至少两个来源不同的公开集合可重复运行；能同时输出证据覆盖和
最终答题指标；冻结留出集不可被生产规则读取；基线报告可由精确 SHA 重建。

### P0-B：建立错误分类和候选准入制度

12. [ ] 用基线逐题归类独立错误簇：时序有效期、撤销/覆盖、冲突事实、多人/多实体、
    多跳关系、名单完整性、偏好/规则记忆、跨语言、长上下文去冗余、无答案抑制。
13. [ ] 对每个错误簇记录样本数、当前准确率、理论可修复上限和误修风险；少于足够独立
    样本的现象只记为假设，不能直接写生产规则。
14. [ ] 建立候选记分卡：冻结答题增益、证据增益、旧集合回退、延迟、峰值内存、数据库
    增长、实现复杂度和可回滚性。
15. [ ] 规定准入阈值：冻结答题主指标必须提升，关键能力不能出现实质回退；若只是召回
    改善而答题不变，候选留在实验分支。
16. [ ] 对 Blind4--Blind11 和旧合成集合重新定位为“回归/诊断”，不再把它们当成
    竞争力主证据。

### P0-C：按独立错误簇升级核心能力

17. [ ] 时序状态：表示事实的 `observed_at / valid_from / valid_to / retracted_at`，明确
    区分陈述时间、事实生效时间和查询时间。
18. [ ] 时序查询：处理未来生效、已过期、被撤销、当前与历史对比；信息不足时保留多方
    证据，避免用脆弱关键词强行删除历史事实。
19. [ ] 冲突治理：以主体-关系-客体和来源时间形成冲突组，保留历史链与当前状态，并让
    排序随查询意图切换。
20. [ ] 多跳证据：从单条排名升级为有界证据组，支持实体桥、关系桥和相邻指代；限制
    跳数、分支和预算，防止噪声爆炸。
21. [ ] 名单完整性：识别集合型问题，优先覆盖不同成员而不是返回同一成员的重复片段；
    单值查询保持高精度。
22. [ ] 个性化和规则记忆：区分稳定偏好、临时安排、用户明确规则和一次性事件；验证
    覆盖/例外行为。
23. [ ] 查询类型路由：只在跨公开集合证明必要时启用，以可审计特征选择时序、集合、
    多跳或普通检索路径；必须有安全默认路径。
24. [ ] 轻量重排：先比较可解释特征重排和低成本本地模型；只有端到端净增益足以覆盖
    延迟、内存和部署风险时才采用交叉编码器或 LLM 重排。
25. [ ] Top-100 去冗余和多样性：限制相同会话/近重复文本占位，保留必要上下文，同时
    测量完整性是否下降。
26. [ ] 多语言泛化：使用公开多语言样本或忠实翻译对照验证；停止为单个词或句式追加
    手写桥接表。

**每个 P0-C 项的完成条件：** 至少一个发展集复现、一个冻结来源验证、旧回归无实质
下降，并保存消融结果。一次只合并一个可解释能力增量。
